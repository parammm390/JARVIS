# FINNOR Phase 1 commercial truth audit

Date: 2026-08-15
Scope: public marketing routes, live deployment, repository product truth, metadata, structured data, sitemap, navigation, public demos, resource routes and interaction systems.

## Audit conclusion before changes

The live site and repository already contain strong evidence of a governed execution product: JARVIS command surfaces, operating read models, action contracts, authority controls, durable workflows, recovery states and decision receipts. The main commercial problem is not missing product proof. It is narrative allocation.

- The homepage, Product, Capabilities, How It Works, Resources and several interactive systems repeatedly explain the same `Context → Plan → Authority → Execution → Evidence` chain. That mechanism dominates what the buyer is purchasing.
- FINNOR and JARVIS are usually described accurately, but plain business language about a company-wide configured deployment arrives too late or not at all.
- Customers, Work, Schedule and Money are visible. Inventory, Quotes, Communication, Research and Agents are not consistently presented as part of the broader configured operating scope.
- “One consequential workflow” reads as the product boundary in multiple calls to action. It needs to be the first certified operating chain within a broader company deployment.
- Pricing is described as custom but the numeric starting point is withheld. This leaves the site looking like an ordinary SaaS product with an evasive price page.
- The implementation work is under-described. Operating review, workflow and source mapping, integrations, policy, workspace setup, recovery testing, onboarding, activation and support need to be visible.
- Company-specific scope differences—locations, roles, authority, approvals, AI policy, channels, agent scope and workspaces—are scattered rather than stated as the deployment model.
- The codebase supports purpose- and channel-aware model/provider routing with deadlines, health ordering and fallbacks, but the public site does not explain multi-model intelligence.
- The public `/demo` correctly labels voice as one instruction channel, yet the surrounding website concierge still contains stale low-cost response-system packages and missed-call/booking language.
- Legacy resource slugs retain `missed-call`, `dispatch-ai`, `admissions-ai` and `pilot` classification signals even where their visible content has already changed.
- Search results still expose an older Trust & Safety crawl focused on booking automation, missed calls and dispatch. Live HTML is newer, but the stale URL vocabulary and inconsistent historical signals make reclassification harder.
- Root metadata and schema still lead with the execution chain. Structured data does not state the customized deployment category or the approximately $30,000 starting deployment.
- The strongest interactive work is the operating model, JARVIS surface, scoped deployment composer, recovery console and policy lab. The additional repeated flow animations can be removed without weakening proof.

## Product truth verified in the repository

- JARVIS exposes command, Work, Customers, Schedule, Money and Agents surfaces and associated read models.
- FINNOR uses registered bounded actions rather than invented capabilities.
- Authority, approval, idempotency, durable workflow state, recovery, reconciliation and receipts exist as execution concerns, not presentation-only claims.
- Model/provider selection is explicit by purpose and channel, can use configured fallback chains, carries latency deadlines and records provider outcomes and cost where reported.
- Voice is a supported channel with additional configuration; text, console, webhook and worker paths also exist.
- Integration health and production activation are configuration facts. The site must continue to avoid claiming that every possible external provider is live.

## Phase 1 change boundary

Preserve the visual system and JARVIS frontend. Reallocate existing marketing sections, rewrite commercial copy and schema, expose deployment scope and starting price, update the public concierge, replace stale resource URLs with permanent redirects, and verify every public route and responsive state.
